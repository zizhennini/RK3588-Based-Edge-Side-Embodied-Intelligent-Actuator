# P1 验收报告：静态定位（手眼标定 + 静差补偿）

> 2026-10-06 ｜ RK3588 + SO-101 从臂 + D435i 固定俯视 ｜ 工具：`tools/handeye_calib.py`
> 关联：`docs/p0_report.md`（P0 离线验收）、`测试方案_VLM+外部IK+抓取.md`（仓库外）

**结论：P1 通过 ✅**，但**不是靠提高硬件精度**，而是靠**软件补偿机械静差**。

| | 中位 | p90 | max | 判据 |
|---|---|---|---|---|
| 直接下发目标（不补偿） | 7.81 mm | 10.79 mm | 11.17 mm | ✗ 中位 >5 mm |
| **静差补偿后** | **1.64 mm** | **4.22 mm** | **4.69 mm** | ✓ 全通过 |

判据（方案 P1）：指定目标点 → IK → 执行 → 相机实测末端偏差 **≤5 mm**，10 个目标点。
10 个随机点（与标定点不重合、相互间隔 >2 cm）**无一个外点**。

---

## 1. 真正的障碍不是 IK，也不是相机

| 环节 | 实测 |
|---|---|
| IK 数值精度 | ✅ 位置残差 **0.16 mm**，标定区域 **16/16** 可达 |
| 单应重投影残差（像素 ↔ 实际末端） | ✅ 中位 **1.23 mm**、p90 3.25、max 4.75 mm |
| **舵机实际到达 vs 下发目标** | ❌ 中位 **9.43 mm**、max 14.04 mm |

即：IK 算得准、相机看得准，**但手臂到不了**。逐关节看偏差集中在**肘 +3.3~3.9°、肩 +2.7~4.6°**；
连读 4 秒 Δq **逐位不变** → 不是"没到位"，而是**静差**。

**根因**：位置环 `DEFAULT_PID = P16 / **I0** / D32`（`hardware/feetech_bus.py`）。
没有积分项时，位置环直流增益有限，**恒定重力矩必然产生恒定偏移**。

## 2. 为什么选择软件补偿而不是调舵机

先试过把 I 设成 16（`--i-term 16`）：

| | I=0 | I=16 |
|---|---|---|
| 肩静差 | +1.71° | **−0.13°** |
| 腕静差 | +2.02° | +1.05° |
| TCP 静差（标定中位） | 9.43 mm | **5.65 mm** |
| 偏航跨度 | 0.49° | **3.24°** ❌ |
| 标记跟踪 | 正常 | **2/16 点误锁到底座暗块**（抖动 140 px、残差 104 mm）❌ |

只加 I 项会让系统**欠阻尼**（需要 D 配合整定），代价是引入振荡。而静差本身是**可重复**的，
于是改走"测出来再扣掉"的路线，不动硬件参数、不引入振荡风险。

## 3. 补偿怎么做的（为什么成立）

在**固定 z + 固定腕部姿态**下，手臂构型由 (x, y) 唯一决定；重力矩随之确定，静差也就确定。
于是 `d(x, y) = 实际 FK − 下发目标` 是一个光滑函数，用 2 阶多项式（1, x, y, x², xy, y²）最小二乘拟合：

| 量 | 实测 |
|---|---|
| 原始静差（下发 vs 实际） | 中位 **9.43 mm**、max 14.04 mm |
| 2 阶模型拟合后残余 | 中位 **2.04 mm**、max 7.68 mm |
| → 可补偿部分 | **7.40 mm**（约 78%） |

下发时用 `cmd = target − d(target)`，验证时测得中位从 7.81 mm → **1.64 mm**。

同时修正了一处**口径错误**：单应原先拟合到「下发目标」，但标记装在手臂上，
它在画面里的像素对应的是"**手臂实际在哪**"。9.43 mm 的静差被整体灌进了单应里。
改成拟合到**实际 FK 位置**后，重投影残差从 3.67 mm 降到 **1.23 mm**。

## 4. 测量链路本身也修了两个坑

1. **标记方案换了三次**（详见工具 docstring）：① 夹爪里的彩色方块 → 被夹爪本体
   **完全挡住**，一个像素都看不到；② 桌面姿态下的黑色矩形面板 → 手臂抬到标定位姿并转
   竖直后它**转到背面**；③ 最终用**腕部黑舵机**（V<60 时 bbox≈(269,183,67,55)、面积 1921、
   填充率 0.52，是画面里最大最亮的暗分量）。
2. **跟踪用 H⁻¹ 预测像素**：原先"沿用上一帧像素"在手臂大幅移动时会误锁到别的暗块
   （实测 2/10 点给出 140 mm 的假数据）。改为用单应逆变换预测标记应有的像素位置并加
   45 px 门限后，**10/10 点全部正常**，中位也从 3.44 mm 进一步降到 1.64 mm。

## 5. 这个结果对 P2 的意义与限制

**意义**：相机→基座的映射与手臂实际到达位置可以做到 **1.6 mm 中位 / 4.7 mm 最大**，
比 2 cm 方块的抓取余量（±10 mm）宽裕，**P2 的抓取在精度上是可行的**。

**限制（必须在 P2 里处理）**：
1. **补偿模型绑定"固定 z + 固定姿态"**。抓取时要在不同高度（下降、抬起）动作，
   z 变化会改变重力矩 → 静差随之变化。P2 需要把模型扩到 `d(x, y, z)`，
   或在每个工作高度各标一次。
2. **绑定当时的舵机整定与负载**。改了 P/I/D、换了夹爪/线材重量、夹了重物，
   模型都失效 → 需重标。
3. 模型只覆盖标定区域 `x∈[0.16,0.26]、y∈[-0.09,0.05]`，区域外是外推，不可信。
4. `config/homography.json` 里存了标定指纹，标定文件一变就会拒绝使用（防止拿旧标定跑新臂）。
   该文件已加入 `.gitignore`（它绑定现场条件，不该入库）。

## 6. 复现步骤

```bash
python tools/handeye_calib.py --status                 # 只读：姿态 + 可行性预检
python tools/handeye_calib.py --check --marker panel    # 只读：相机能否看到标记
python tools/handeye_calib.py --recover --confirm-motion # 从折叠姿态恢复到已验证姿态
python tools/handeye_calib.py --calibrate --confirm-motion --grid 4 --marker panel
python tools/handeye_calib.py --verify --confirm-motion --points 10 --verify-mode both
```

## 7. 过程事故记录（都已修复）

- **夹爪过载锁死**：`--grip-until-contact` 夹住后没有回退，持续堵转约 3 分钟，
  温度 37→45℃，舵机锁死 Overload 保护态（寻址 ping 不应答、只能直读寄存器）。
  已修：检测到接触后强制回退 4 mm；恢复方法是给从臂断电重上电。
- **释放扭矩导致折叠下坠**：释放后机械臂折叠到 TCP 离基座仅 ~5 cm 的**近奇异**构型，
  笛卡尔 IK 在那里发散（实测抬升到一半偏出 44 mm）。已修：新增 `--recover` 走关节空间插值；
  并把"保持扭矩"改为默认（`--release` 才放开）。
- **`configure()` 覆盖 P/I/D**：`connect()` 内部会按 `DEFAULT_PID` 重写 P/I/D，
  任何 I 项改动必须在 connect **之后**写，否则被覆盖。
- **prompt/统计口径类**：曾在 `draw_candidates` 画过红框的图上做颜色统计，
  把注释框当成方块（P0 报告的同类教训）。
